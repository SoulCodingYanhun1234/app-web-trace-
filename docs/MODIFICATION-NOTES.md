# 本次修改说明

## 装箱管理

- 已移除箱码分类的接口可写字段、列表展示扩展、CSV 列和二维码 ZIP 分类目录。
- 产品自身的产品分类功能不受影响。

## 代理商所属地区

- `agents` 新增可空字段 `district`，用于保存区县。
- 省、市、区县会进入代理商查询、下拉选项、产品归属、装箱与发货地区快照。
- 只选择省级也可保存；市级和区县级均为可选的进一步细化。

## 2026-07-23：根路由、AI 溯源与防窜边界

- AI 模型接口调整为“AI 溯源研判”，统一使用 `trace:view` 权限。
- AI 总览、任务与单条分析围绕产品、批次、防伪码及溯源节点完整性展开。
- 防窜预警在服务端增加码类型硬限制：仅 `anti_fake_code`（防伪码）进入防窜评估。
- 装箱码、产品码、溯源码、发货码及其他业务码不会生成防窜预警；发货预检仍保留代理商地区资料完整性校验。
- 查询端与扫码端均显式传递码类型，避免箱码或其他码误入防窜规则。
- 本次涉及的后端源码与 `dist` 已同步更新并通过 JavaScript 语法检查。
- 当前沙箱无法联网安装依赖，因此未执行完整的 `npm ci` / Nest 构建；部署环境仍建议按原流程运行 `npm ci && npm run build`。

## 2026-07-23：AI 自动化溯源任务中心

- 新增 `/trace/automation/overview` 与 `/trace/automation/run`，统一巡检产品、防伪码、溯源、装箱、发货和防窜数据。
- 自动任务可重放产品建档、防伪码建链、装箱/封箱、发货/签收和市场扫码复核，并返回逐模块执行结果。
- 固定自动化节点使用稳定 `trace_key` 幂等合并，避免重复执行无限追加节点。
- 防窜自动巡检只处理数据库中存在的防伪码；箱码、发货码、产品码、溯源码和其他业务码全部跳过。
- 后端源码与 `dist/resources` 已同步；由于包仓库 503，未执行依赖完整构建。
